# Security notes

## Security notes

The server accepts only requests that come from its own page: it checks the Host and Origin headers (a POST without an Origin is refused) and a token generated at each launch. The page itself is served only to a browser the launcher opened: the server writes a one-use nonce to `%LOCALAPPDATA%\AetherReconStudio\launch-nonce.txt`, the launcher opens `/?n=<nonce>`, the server answers with an HttpOnly, SameSite=Strict cookie and replaces the nonce. A request to `/` without that cookie gets a note and no token. This keeps out other Windows accounts and sandboxed programs that cannot read your profile; a program running as you can still read the nonce file, so do not run the studio on a machine whose other programs you do not trust. The server needs a full-path workspace (not a drive root, not inside the studio or tool folders, and not inside another workspace), accepts only an empty folder or one the studio made (a `.run.json` with a package hash), limits file reads and script copies to that workspace, and runs one recovery, audit, install or Craft Anything run at a time. A run lock has an owner, so a late finish cannot release another run's lock. **Agents are tracked, not sandboxed.** While an agent the studio opened is working in a workspace (a command-line agent, until its process ends; a desktop app, until you press "Agent finished"), the studio refuses stages, audits, script exports, the scaffold preset, Open in Unity, Craft Anything and tool installs there. The agent itself can still edit anything the workspace holds, including `.run.json` and the audit files, so treat an audit as trustworthy only when you ran it yourself after the agent finished. Tool installs from the Tools tab are extracted to a temporary folder and moved into place only if they contain the expected files. They must match the SHA-256 digest published with the GitHub release, the download may be redirected only to GitHub hosts over https and is limited to 2 GB, and zip paths are checked before extraction. REA, which installs through npm, is approved by version: the studio refuses to install anything but the version npm lists as newest when you approved it, always from the public registry with no user or project npm config, with `--ignore-scripts`, and checks the installed version afterwards. npm's own integrity data covers the package; there is no separate digest. A digest from the same release page detects a corrupted download, not a compromised release. Craft Anything's CLI must be a `craft-anything-cli` program that sits on PATH (not the current folder) or in a folder you set up (the tool root, `%USERPROFILE%\.cargo\bin`, Program Files, `%LOCALAPPDATA%\Programs`), never a file inside a workspace. Opening a project in Unity compiles its scripts, so the button asks you to confirm it.
